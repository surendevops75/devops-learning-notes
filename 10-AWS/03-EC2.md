# Amazon EC2 (Elastic Compute Cloud)

---

# Introduction

Amazon Elastic Compute Cloud (Amazon EC2) is a web service that provides secure, resizable, and scalable virtual servers (called Instances) in the AWS Cloud.

EC2 allows you to launch Linux or Windows virtual machines within minutes without purchasing physical hardware.

It is one of the most widely used AWS services and forms the foundation for hosting web applications, APIs, databases, CI/CD tools, monitoring tools, Kubernetes worker nodes, and enterprise workloads.

---

# What is EC2?

EC2 is Infrastructure as a Service (IaaS).

It provides:

- Virtual Servers
- CPU
- Memory
- Storage
- Networking
- Security
- Elastic Scaling

without managing physical servers.

# EC2 Best Practices

- Use IAM Roles instead of Access Keys.
- Enable detailed monitoring.
- Use Security Groups instead of opening all ports.
- Use Auto Scaling.
- Deploy across multiple AZs.
- Enable backups.
- Keep AMIs updated.
- Patch regularly.
- Use Launch Templates.
- Use Systems Manager.

---

# Common Mistakes

- Using Root User.
- Opening SSH to the world.
- Hardcoding credentials.
- Not enabling backups.
- No monitoring.
- Large unused instances.
- Forgetting to terminate test instances.
- Using public IP unnecessarily.

# Key Takeaways

- Amazon EC2 provides scalable virtual servers in the AWS Cloud.
- AMIs are templates used to launch EC2 instances.
- Instance Types define CPU, memory, storage, and networking capacity.
- Use IAM Roles instead of long-lived access keys.
- Deploy instances across multiple Availability Zones for high availability.
- Protect instances using Security Groups and least-privilege access.
- Monitor EC2 with CloudWatch and automate operations using Systems Manager.
- Use Auto Scaling and Load Balancers to build resilient, production-ready architectures.
