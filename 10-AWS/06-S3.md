# Amazon Simple Storage Service (Amazon S3)

---

# Introduction

Amazon Simple Storage Service (Amazon S3) is a fully managed, highly durable, scalable, secure, and cost-effective object storage service provided by AWS.

Unlike Amazon EBS and Amazon EFS, which are block and file storage services respectively, Amazon S3 stores data as **objects** inside **buckets**. It is designed to store virtually unlimited amounts of structured and unstructured data while providing high durability, availability, and security.

Amazon S3 is one of the oldest and most widely used AWS services. It is the storage backbone for many AWS services and is commonly used for application assets, backups, logs, static websites, media files, data lakes, machine learning datasets, and disaster recovery.

---

# What is Amazon S3?

Amazon S3 is an **Object Storage Service**.

Everything stored in Amazon S3 is called an **Object**.

Objects are stored inside **Buckets**.

Example:

```
Bucket

├── image1.png

├── invoice.pdf

├── backup.zip

├── logs/

│      ├── app.log

│      └── nginx.log

└── videos/

       └── demo.mp4
```

Unlike traditional file systems, S3 has no real directory hierarchy. Folder structures are logical prefixes created as part of the object key.

# Why Amazon S3?

Imagine a web application running on multiple EC2 instances.

```
EC2-1

↓

Uploads image

↓

Local Disk
```

When another server receives a request:

```
EC2-2

↓

Image Missing
```

Local storage causes inconsistency.

Using Amazon S3:

```
Application

↓

Amazon S3 Bucket

↓

Any EC2 Instance

↓

Read Same Object
```

Every application server accesses the same object regardless of which server processed the upload.

# Object Storage vs Block Storage vs File Storage

| Feature | Amazon S3 | Amazon EBS | Amazon EFS |
|----------|-----------|------------|------------|
| Storage Type | Object | Block | File |
| Mountable | No | Yes | Yes |
| Shared Storage | Via API | No | Yes |
| Capacity | Virtually Unlimited | Fixed | Elastic |
| Protocol | HTTP/HTTPS | Block Device | NFS |
| Use Case | Images, Logs, Backups | OS, Databases | Shared Files |

# Durability

Amazon S3 is designed for **11 nines (99.999999999%) durability**.

AWS automatically stores multiple copies of each object across multiple devices within the selected Region.

If a storage device fails, S3 automatically recreates redundant copies without user intervention.

---

# Availability

Amazon S3 provides high availability through redundant infrastructure within an AWS Region.

Applications can continue accessing data even if individual storage devices fail.

---

# Scalability

Amazon S3 automatically scales without manual intervention.

You never need to:

- Add disks
- Resize storage
- Create RAID arrays
- Increase capacity manually

Storage grows automatically as objects are uploaded.

---

# Data Consistency

Amazon S3 provides **strong read-after-write consistency** for:

- PUT
- DELETE
- LIST

Once an upload completes successfully, any subsequent read immediately returns the latest version of the object.

# Amazon S3 Storage Classes

Amazon S3 provides multiple storage classes to optimize cost based on data access patterns.

Choosing the correct storage class is one of the most important decisions for cost optimization.

---

# Storage Class Overview

| Storage Class | Availability | Retrieval Speed | Cost | Best For |
|---------------|-------------|-----------------|------|----------|
| Standard | High | Milliseconds | High | Frequently accessed data |
| Intelligent-Tiering | High | Milliseconds | Medium | Unknown access patterns |
| Standard-IA | High | Milliseconds | Lower | Infrequently accessed files |
| One Zone-IA | Single AZ | Milliseconds | Low | Re-creatable data |
| Glacier Instant Retrieval | High | Milliseconds | Very Low | Archives needing instant access |
| Glacier Flexible Retrieval | Archive | Minutes to Hours | Very Low | Long-term backups |
| Glacier Deep Archive | Archive | Hours | Lowest | Compliance & archival |

# Encryption

Amazon S3 supports multiple encryption methods.

## SSE-S3

AWS manages encryption keys.

Simplest option.

---

## SSE-KMS

AWS KMS manages encryption keys.

Provides:

- Key rotation
- Auditing
- Access control

Recommended for enterprise workloads.

---

## SSE-C

Customer supplies encryption keys.

AWS never stores the key.

Suitable for organizations with external key management requirements.

# Terraform

Create Bucket

```hcl
resource "aws_s3_bucket" "app" {

  bucket = "company-prod-storage"

}
```

Enable Versioning

```hcl
resource "aws_s3_bucket_versioning" "versioning" {

  bucket = aws_s3_bucket.app.id

  versioning_configuration {

    status = "Enabled"

  }

}
```

Enable Encryption

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "default" {

  bucket = aws_s3_bucket.app.id

  rule {

    apply_server_side_encryption_by_default {

      sse_algorithm = "aws:kms"

    }

  }

}
```

Block Public Access

```hcl
resource "aws_s3_bucket_public_access_block" "security" {

  bucket = aws_s3_bucket.app.id

  block_public_acls       = true

  block_public_policy     = true

  ignore_public_acls      = true

  restrict_public_buckets = true

}
```

# Summary

Amazon S3 is the foundational object storage service in AWS. It provides virtually unlimited, highly durable storage with strong consistency, enterprise-grade security, lifecycle management, replication, and deep integration with AWS services. S3 is widely used for application assets, backups, logs, Terraform state, CI/CD artifacts, analytics, and disaster recovery.

For production environments, always enable Versioning, Server-Side Encryption, Block Public Access, Lifecycle Policies, CloudTrail logging, and least-privilege IAM access. Combine S3 with CloudFront for global content delivery and use appropriate storage classes to optimize long-term costs.
